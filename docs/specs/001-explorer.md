# 001. Визуальный проводник истории

## 1. Цель и границы

**Статус: Вехи 1 и 2 завершены. Миникарта подключена к существующей компоновке; уточнения управления островками сохраняются следующим логическим изменением. Веха 3 не начата.**

Основание — [согласованное поведение проводника](../spec_chat_explorer.md) и оставшиеся этапы 3а–7 [ROADMAP](../../ROADMAP.md). Этот файл организует выполнение, не заменяет подробную спецификацию. Подготовка CI и локального workflow выполнена отдельно; успешный удалённый прогон CI в этой задаче не проверялся.

**In Scope:** происхождение слияний с сохранением существующих данных, компактный API графа, миникарта в существующей панели, навигация к реплике, выбор ветки, ограниченное окно отображения с подгрузкой в обе стороны, синхронизация и документация реализованного поведения.

**Out of Scope:** изменение UX перегенерации, вложения и диктовка, редактирование из графа, drag-and-drop слияние, массовые операции, оконный менеджер, подсветка видимого участка ленты и полная реорганизация документации.

## 2. Ключевые решения и контракты

- Сплошные рёбра соответствуют `parent_id`; пунктирные показывают происхождение конкретной сводки. Пунктир не добавляет родителя и не меняет контекст ветки или алгоритм инкрементального слияния.
- Добавлено nullable `MergeEvent.source_head_message_id`: фактическая вершина источника на момент слияния. Новые события сохраняют её атомарно с результатом слияния; проверяется принадлежность сообщения тому же чату. Существующие поля сохраняют назначения.
- Миграция Alembic сохраняет чаты и сообщения. Все старые события получают `NULL` без автоматического восстановления; точное пунктирное ребро для них отсутствует.
- Отдельный read-only контракт графа должен давать компактные узлы с превью, связи и указатели веток без полных Markdown-текстов всей истории. Утверждён `GET /api/v1/chats/{chat_id}/graph`; backend-контракт реализован в Вехе 1. SQL/ORM — в storage, сценарий — в сервисе, HTTP и DTO — в API, раскладка и камера — на фронтенде.
- Узлы — небольшие точки без постоянных подписей; формы различают роли, цвета обозначают ветки, превью доступно по наведению и клавиатурному фокусу. Общие сообщения не дублируются, скрытые остаются видимыми. Граф идёт сверху вниз, ответвляется вбок и вниз плавными кривыми; активная ветка выделяется. Камера независима от обычной прокрутки чата.
- При переходе сохраняется текущая ветка, если содержит узел; иначе выбирается единственная подходящая или предлагается выбор из нескольких. Маска не запрещает навигацию. Вокруг далёкой цели открывается ограниченный участок ленты с подгрузкой в обе стороны и сохранением позиции; это не окно контекста LLM.
- Граф обновляется после существующих операций чата. Поздние ответы другого чата не перезаписывают выбранные данные; правки текста и масок не сбрасывают камеру произвольно. Живой Gemini в автоматических проверках не вызывается.
- Работа начинается только после утверждения вехи и разрешения её контрактных вопросов. Каждая веха завершается relevant suite, self-review и атомарными коммитами по глобальному протоколу; зависимости и миграции перечисляются в отчёте. Наличие незавершённого UI не позволяет выдать веху за принятую.

### Утверждённый контракт Вехи 1

- Ответ: `chat_id`, `nodes`, `branches`, `merges`. Возвращаются все сообщения (включая скрытые и не входящие в текущие ветки) и все статусы веток одним ответом из согласованного снимка чтения.
- Узел: `id`, `parent_id`, `role`, `preview`, `preview_truncated`, `is_active`, `is_edited`, `created_at`, `updated_at`. Превью — первые 200 символов после объединения пробельных последовательностей, обычный текст; полные тексты и metadata не передаются.
- Ветки используют существующий `BranchResponse`. Слияние: `message_id`, `source_branch_name`, nullable `source_head_message_id`, `compressed_messages_count`. Отдельного массива рёбер и координат нет.
- `200`: существующий чат, в том числе пустой; `404`: неизвестный чат; `500`: нарушенная целостность с безопасным общим сообщением. Неизвестный старый источник — штатный `NULL`.
- Источник нового слияния — фактический HEAD, даже скрытый, с составным внешним ключом по чату. Новая миграция `0002` не меняет существующие связи истории. Принятие pre-Alembic базы остаётся регистрацией baseline `0001`, затем выполняется upgrade.
- Узел без подходящей ветки показывается на будущей карте без автоматического создания ветки. Существующий timeline не изменяется; новый UX будет реализован в Вехе 3.

### Утверждённое представление Вехи 2

- USER — заполненный круг, MODEL — окружность без заливки, SYSTEM_MERGE — ромб. Скрытые узлы приглушены и имеют пунктирную обводку. Активная ветка выделяется яркостью и толщиной связей.
- Main голубая; остальные ветки получают стабильный цвет по ID из спокойной конечной палитры. Общие предки main голубые; для других пересечений выбирается стабильный порядок веток. Повторение оттенков допустимо.
- История идёт сверху вниз, продолжения расходятся вбок и вниз плавными кривыми. Пунктир происхождения не меняет раскладку цепочек. Возле HEAD показываются сгруппированные названия веток.
- ЛКМ выбирает узел и закрепляет превью; клик по фону снимает выбор. Перемещение — средней кнопкой либо Space + ЛКМ; колесо масштабирует. Панель кнопок: плюс, минус и иконка четырёх углов с доступными названиями.
- Превью доступно по наведению и фокусу, показывает роль, UTC-время в локальном отображении, текст и флаги; у слияния — источник. Начальная камера показывает HEAD активной ветки; положение хранится только в памяти по чату, включая закрытие панели.
- Граф загружается только при открытой панели; смена чата очищает прежние данные, отменённый или поздний ответ игнорируется. Ошибки и ручное обновление находятся внутри панели и не блокируют чат.
- Двойной клик и Enter зарезервированы под переход к сообщению в Вехе 3; двойной клик не масштабирует граф. ПКМ, рамка выделения и массовые действия пока не реализуются. В этой вехе нет автоматической синхронизации после операций — есть кнопка обновления.

## 3. Вехи и чек-лист

### Веха 1. Достоверные данные и контракт графа

- [x] **Mode C: Docs.** Согласованы DTO, маршрут, ошибки, старые источники `NULL` без восстановления и изменение ожидания ревизии в тестах на этапе RED.
- [x] **Mode A: TDD.** RED → GREEN: миграция происхождения слияний, сохранность старой истории, неизвестные старые источники без восстановления. Изменение ожидания ревизии и подготовка baseline согласованы и выполнены на этапе RED.
- [x] **Mode A: TDD.** RED → GREEN: атомарное сохранение источника новых и повторных слияний; storage-чтение компактного графа, отсутствие дублей и изоляция по чату.
- [x] **Mode A: TDD + Mode C: Docs.** Contract-First: тонкий API графа, контрактные и интеграционные проверки, обновление фактического справочника и чек-листа; self-review и коммиты.

### Веха 2. Отображение миникарты

- [x] **Mode A: TDD.** RED → GREEN: типы и HTTP-клиент графа, загрузка и ошибки состояния, защита от позднего ответа после смены чата.
- [x] **Mode B: Smoke.** Подключить React Flow, выбрать и зафиксировать раскладку; показать уникальные точки, формы ролей и цвета веток, скрытые узлы, два вида рёбер и активную ветку в существующей панели.
- [x] **Mode A: TDD + Mode B: Smoke.** Проверить интерактивные превью и клавиатурный доступ, состояния выбора, независимую камеру, открытие и изменение размеров панели; визуальные параметры проверить в браузере.
- [x] **Mode B: Smoke + Mode C: Docs.** Браузерные проверки отображения и отсутствия runtime-ошибок, relevant suite и документация реализованного. **[STOP: Manual Review]** Проверка плотности, цветов, превью и поведения камеры пользователем перед завершающим коммитом вехи.

Приёмка вехи: рабочее отображение миникарты; переходы к далёким сообщениям относятся к вехе 3. После приёмки — коммиты, отчёт и остановка.


### Веха 3. Навигация, синхронизация и приёмка

- [ ] **Mode A: TDD.** RED → GREEN: ограниченное окно ленты вокруг цели, догрузка в обе стороны и сохранение позиции чтения на длинной истории; граничные случаи без одновременного рендеринга всего хвоста.
- [ ] **Mode A: TDD.** RED → GREEN: переход внутри текущей ветки, переключение в единственную подходящую, выбор из нескольких, скрытые и общие узлы, выделение цели.
- [ ] **Mode A: TDD.** RED → GREEN: синхронизация после генерации, создания ветки, правки, маски, перегенерации и слияния; смена чатов, конкурентные загрузки и сохранение камеры.
- [ ] **Mode B: Smoke.** Playwright с подменой Gemini: сквозная навигация по длинной истории, изменение размеров, отсутствие runtime-ошибок и проверка объёма DOM. Проверить новые тесты в существующем CI после публикации пользователем.
- [ ] **Mode C: Docs.** Синхронизировать фактические reference, explanation и how-to, отметить выполненные пункты ROADMAP; выполнить self-review и полный relevant suite. **[STOP: Manual Review]** Пользователь проверяет переходы, выбор ветки и плавность подгрузки; после подтверждения — завершающие коммиты и отчёт.

## 4. Открытые вопросы и сопутствующие находки

- Контракт Вехи 1 утверждён. Источники старых слияний не восстанавливаются. Восстановление при необходимости потребует отдельной задачи.
- В `tests/test_database.py` на утверждённом этапе RED ожидание новой базы обновлено до `0002`, а подготовка pre-Alembic баз закреплена на `0001`. Ожидание baseline после adoption сохранено. Во время GREEN существующие тесты не менялись.
- Перед навигацией выбрать размер окна, порций и способ получения участка истории. Если потребуется изменение контракта timeline, сначала согласовать совместимость и контрактные тесты; текущий API не объявляется заменённым заранее.
- В Вехе 2 установлен `@xyflow/react` 13.0.2 (MIT). Дополнительной библиотеки раскладки нет: глубина по parent_id, полосы по стабильному владельцу-ветке, main на основной вертикали. Код компонента и стили React Flow загружаются лениво. Формы и палитра приняты пользователем.
- На первом RED-прогоне несколько subprocess Alembic превысили существующий таймаут 30 секунд. Сфокусированный GREEN-прогон (16 тестов) и полный backend-прогон (203 теста) затем прошли без изменения таймаута или ослабления проверок.
- Локальные проверки не подтверждают успешный запуск GitHub Actions. Публикация, push и merge требуют отдельного указания пользователя; они не входят в эти вехи автоматически.
- Подсветка видимых сообщений и новый UX перегенерации остаются отдельными будущими задачами. Обнаруженные по ходу реализации посторонние ошибки фиксируются здесь без расширения объёма работ.

- Vite предупреждает о директиве `use no memo` в транзитивном `react-compiler-runtime` React Flow. Сборка проходит; предупреждение не подавлялось. Зафиксировано как ограничение текущей связки инструментов.

- По разрешению пользователя в новом E2E-тесте DOM-тип `HTMLElement` заменён структурным типом `{ style: { color: string } }`; ожидания теста сохранены. Обзор 606 узлов проверен после исправления минимального масштаба и явного процентного отступа `15%` для React Flow 13.
- Проверка отдельного снимка Вехи 2: 53 Vitest-теста, TypeScript/Vite build и 4 Playwright-сценария на Edge с одним worker и без retries прошли. Backend и миграции в Вехе 2 не менялись. Это результаты базового этапа до дополнительных уточнений; окончательная ручная приёмка теперь подтверждена.

- При выделении коммита миникарты старый размер панели воспроизвёл перекрытие кнопки увеличения верхним превью; существующий браузерный тест упал. Над превью зарезервировано место для управления камерой; повторный прогон всех 4 сценариев прошёл без изменения ожиданий.
