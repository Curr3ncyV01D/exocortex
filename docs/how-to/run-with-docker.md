# Как запустить ExoCortex через Docker Compose

Понадобится Docker Desktop с Linux-контейнерами или Docker Engine с Compose. Выполняй команды из корня репозитория.

## Запуск

Для живой генерации скопируй `.env.example` в `.env` и задай `GEMINI_API_KEY`. Чаты, ветки и просмотр истории доступны и без ключа.

```sh
docker compose up --build
```

Открой [ExoCortex](http://127.0.0.1:8080/) или [Swagger](http://127.0.0.1:8080/docs). Nginx раздаёт собранный фронтенд и проксирует API на FastAPI. Бэкенд применяет Alembic при старте, затем Compose дожидается его готовности перед запуском фронтенда.

Остановить приложение можно командой `docker compose down`. SQLite, экспорты и резервные копии остаются в каталоге `data/` на хосте. При следующем запуске используется та же база.

## Подключение существующей базы

Если `data/exocortex.db` создана до Alembic, останови другие процессы, работающие с ней. Для перехода достаточно один раз выполнить эти команды.

```sh
docker compose build backend
docker compose run --rm --no-deps backend python -m scripts.adopt_legacy_db
docker compose up --build
```

Скрипт сохранит резервную копию в `data/` и проверит совместимость схемы перед регистрацией ревизии. Уже зарегистрированную SQLite можно открыть обычным запуском. [Как проверить и обновить базу вручную](migrate-sqlite.md)

## Настройки локального запуска

В `.env` можно задать `EXOCORTEX_PORT`, если порт `8080` занят. `EXOCORTEX_DATA_DIR` позволяет выбрать другой существующий каталог для базы, экспортов и резервных копий. Compose по-прежнему публикует порт только на `127.0.0.1`.

На Linux бэкенд по умолчанию пишет в каталог данных с UID и GID `1000`. Если идентификаторы владельца отличаются, задай `EXOCORTEX_UID` и `EXOCORTEX_GID` значениями из `id -u` и `id -g`. У пользователя контейнера должны быть права на запись в каталог данных.

При сбое запуска проверь `docker compose ps -a` и `docker compose logs backend`. Состояние `healthy` означает, что Alembic завершил обновление и FastAPI отвечает на локальном порту контейнера.

## Диагностика Gemini

После пересборки открой журнал `docker compose logs -f backend` и повтори запрос. HTTP `502` в журнале доступа отражает ответ ExoCortex. Строка `gemini_request_failed` сохраняет исходный статус Gemini либо тип сетевого сбоя. События одного хода можно сопоставить по `turn_id`.

| Запись в журнале | Что проверить |
| --- | --- |
| `phase=initial` | Сбой на первом запросе к Gemini, до выполнения локальных инструментов этого хода. |
| `gemini_tool_failed` | Сбой локального инструмента. В строке указаны инструмент и класс ошибки. |
| `phase=after_tools` | Ошибка следующего запроса Gemini после инструментов. Сопоставь статус с предыдущими событиями `gemini_tool_finished`. |
| `gemini_tool_context_over_budget` | Результаты инструментов вместе с контекстом превысили лимит. Агент переходит к завершающему запросу без очередного вызова инструментов. |
| `kind=proxy`, `kind=transport` или `kind=timeout` | Проверь доступность Gemini и сетевые настройки именно из контейнера. |
| `phase=summarize` | Сбой при создании сводки для слияния. |

Сравни короткий и длинный чат в одном контейнере и на одной модели. Поле `context_bytes` показывает размер сериализованной истории на запросе в байтах. Для длинного чата попробуй отдельно запрос, требующий поиска старых реплик, и простой запрос по свежему контексту. [Коды ошибок Gemini](https://aistudio.google.com/docs/api-errors)

В поле `detail` теперь записывается полный текст исключения. Его переносы строк экранируются, чтобы событие занимало одну строку. Тело ответа Google может содержать сведения о запросе, поэтому проверь журнал перед публикацией.

При генерации временные ошибки 503/504, таймауты и обрывы соединения повторяются до трёх попыток с паузами 1,5 и 3 секунды и случайной добавкой до 0,5 секунды. Встроенные повторы SDK для этой операции отключены, чтобы попытки не перемножались. По умолчанию одна попытка ограничена 300 секундами, весь ход и суммаризация — 1800 секундами, включая инструменты и паузы. Все попытки и завершающая ошибка используют один turn_id. Пауза и новая попытка разрешены только в пределах оставшегося бюджета. Ошибка 400 требует разбора полного сообщения Google.

Агент по умолчанию выполняет до восьми итераций инструментов, затем синтезирует итог из найденных сведений. Общий предел остаётся 12 вызовов инструментов за ход.

Генерация и суммаризация используют общую политику повторов. Параметры GEMINI_REQUEST_TIMEOUT_SECONDS и AGENT_OPERATION_TIMEOUT_SECONDS можно задать в .env. Nginx ожидает ответ до PROXY_READ_TIMEOUT_SECONDS (по умолчанию 1860 секунд). При увеличении общего бюджета операции увеличь и этот предел, оставив запас для ответа API. После изменения переменных выполни docker compose up --build -d.

Интерфейс и API работают на одном origin через Nginx. Разрешения CORS для сторонних сайтов отключены; отдельный браузерный клиент с другого origin требует явно согласованной политики доступа. Локальный Vite также использует прокси `/api/`.
